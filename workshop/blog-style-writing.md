# 작업 아이디어 정의

## 작업 이름

블로그 스타일 학습·원고 작성 (style prompt / context pack → 초고 → 첨삭)

## 해결하려는 문제

이미 블로그를 쓰는 사람이 Agent에게 글을 맡기면, 기존 글과 다른 **일반 AI 문체**가 나온다. 글 코퍼스는 있는데 재사용 가능한 스타일 프롬프트·콘텍스트로 안 남아 있고, 초고와 게시 가능 원고의 경계도 없다.

## Agent가 수행할 작업

1. 작성자 본인 블로그에서 글을 수집한다 (Web Crawler Craft 사용)
2. 관찰 가능한 문체를 스타일 프롬프트와 근거 콘텍스트로 만들고 갱신한다
3. 주제에 맞춰 그 스타일로 초고를 쓴다
4. 스타일·완성도를 기준으로 첨삭해 게시 가능한 원고를 만든다

게시는 사람이 한다. Agent는 플랫폼에 올리지 않는다.

## 기대 결과물

- 재사용 스타일 팩: `profile.md`(프롬프트) + `evidence.md`(근거) + 코퍼스 인덱스
- 게시 가능한 마크다운 원고와 첨삭 로그

## 현재 방식과 불편한 점

요청마다 “내 말투로”라고만 하면 Agent가 일반 블로그 조언을 채워 넣는다. 기존 글을 붙여 넣어도 다음 글에 스타일이 남지 않는다.

## 실행 시점 또는 조건

- 스타일 팩이 없거나 오래됐으면 수집·추출부터
- 주제만 주고 글을 맡기면 기존 스타일 팩을 로드한 뒤 초고→첨삭
- 초고만 / 첨삭만 요청되면 해당 단계만

## 판단 기준과 제약

- 스타일 주장은 코퍼스 근거가 있어야 한다. 사실 / 관찰 / 가정을 구분한다
- 작성자가 말하지 않은 경험·수치·의견을 만들지 않는다
- “더 전문적으로” 고치며 문체를 일반화하지 않는다
- 수집은 요청자가 지정한 본인 공개 글만. 크롤 절차는 Web Crawler Craft에 맡긴다

## 완료 조건

- 스타일 팩이 증거 없이 일반론만 담지 않는다
- 초고가 스타일 팩을 로드한 뒤에 쓰인다
- 첨삭 후 사람 확인 항목이 남아 있고, 자동 게시가 없다

## 가정과 아직 결정하지 못한 점

- 플랫폼은 고정하지 않는다. Velog·Tistory·개인 사이트 등 공개 URL이면 된다
- 기본 수집 범위는 최근 글 8~15편. 전체 아카이브는 요청 시에만
- 스타일 팩·코퍼스는 **소비 프로젝트**에 둔다. 이 예시 저장소에 실제 원문을 넣지 않는다
- 미세조정·외부 학습 API는 ver0 범위가 아니다
- 실제 본인 블로그 URL 실험은 이 공방이 아니라 소비 저장소 `blog_agnet`에서 한다
- `.cursor/` 승격은 하지 않는다

## 상태

`draft` — 이 저장소 최소 예시는 여기까지. 실제 수집·초고·첨삭은 `blog_agnet`에서 돌리고, 관찰만 이 공방에 되돌린다.

## fixture 드라이런 (2026-08-26)

`fixtures/sample-corpus/` 3편에 `build-style-context`를 적용해 `fixtures/sample-style-pack/`을 남겼다.

바로 도움이 된 것:

- 해요체, 짧은 문단, 장면형 도입, “다음에 내가 해볼 것” 맺음, 소제목 없음이 인용과 연결됨
- “교훈을 세 줄로 정리하고 싶진 않아요”가 ‘하지 않는 것’ 근거가 됨

아직인 것:

- 3편이라 제목 패턴은 가정으로 남김
- 실제 URL 수집·첨삭은 `blog_agnet`에서 할 일

다음 실험은 `blog_agnet`에서 한다. 이 공방에는 아래만 되돌린다.

```md
## 관찰 (blog_agnet)

1. 바로 도움이 된 내용
2. 불필요하거나 과도했던 내용
3. 다음 실행에서 바꿀 한 가지

- 수집 경로: RSS / 내부 API / HTML (원문 URL 목록은 선택)
- 팩이 일반 작법으로 샜는지
- 첨삭이 문체를 평탄화했는지
- Rule·Skill에 손댈 점 (있으면)
```

원문, 스타일 팩 전문, 원고 전문은 공방 예시에 복사하지 않는다.

## 관찰 (blog_agnet → Issue #11, 2026-08-27)

소비 프로젝트에서 첫 글을 게시하고 사용 기록을 이 공방 Issue로 보냈다. [Issue #11](https://github.com/geunsu-son/agent_skill_bundle/issues/11)

1. 수집 → 팩 → 원고 순서가 그대로 따라졌다. 주제 정리 md만으로 초고가 나왔다.
2. 글마다 말투가 조금 달라 팩을 나눌지 이야기했으나, **팩 하나 + 글 안 조정**으로 진행했다. 이 합의는 Blog Style Writing Skill에 넣지 않는다.
3. 피드백 초안이 사용 맥락을 Skill 패치로 올리기 쉬워, `report-bundle-feedback`만 사용 기록 중심으로 고친다.

초고 Skill을 fixture 팩으로 한 번 적어 본 결과: 제공 사실 밖의 장애 시각을 `[확인 필요]`로 남기면 장면형 도입과 충돌하지 않았고, “팀이 따라올지”처럼 입력에 없는 추측은 첨삭에서 빼는 편이 맞았다. 최종 원고는 예시에 커밋하지 않았다.
