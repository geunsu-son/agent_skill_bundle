# BNF 트레이딩 전략 PDF 분석 결과

## 블로그 글 제목 후보

**BNF 트레이딩 전략을 AI로 분석해 보니: 모델별 토큰 사용량과 품질 비교**

## 출처와 실험 조건

- 대상 문서: `BNF_Trading_Strategy_Transcript.pdf`
- 비교 모델: GPT-5.6 Luna, Composer 2.5, Grok 4.6, Auto
- 1단계: PDF 전체를 읽고 `OK`만 출력
- 2단계: 동일한 형식으로 핵심 내용, 진입 조건, 손절·익절 원칙, 위험 요소를 요약
- 사용량 기준: Cursor `usage-events` CSV의 `Total Tokens`

## 결과

| 단계 | GPT-5.6 Luna | Composer 2.5 | Auto | Grok 4.6 |
|---|---:|---:|---:|---:|
| PDF 입력만 처리 | 40,019 | 40,412 | 40,649 | 41,596 |
| PDF 분석·요약 | 40,681 | 41,421 | 59,591 | 662,210 |

1단계에서는 Luna가 기준일 때 Composer 2.5가 0.98%, Auto가 1.57%, Grok 4.6이 3.94% 더 많았다. 단순히 PDF를 읽는 입력 처리량은 네 모델이 큰 차이를 보이지 않았다.

2단계에서는 Composer 2.5가 Luna보다 1.82%, Auto가 46.5%, Grok 4.6이 약 16.3배 더 많았다. Grok은 표시 답변을 800자 이내로 제한했지만, CSV에는 출력 29,045토큰과 캐시 읽기 494,720토큰이 기록되어 표시 답변 길이만으로 사용량을 판단할 수 없었다.

## 품질 관찰

- GPT-5.6 Luna: 네 가지 요구 항목을 모두 다루고, PDF에 구체적인 손절 수치가 없다는 점을 명시했다. 품질 1위로 평가됐다.
- Composer 2.5: Luna와 큰 차이 없이 좋은 결과를 냈고, 간결성이 강점이었다.
- Auto: 무난했지만 실제 라우팅 모델을 CSV만으로 확인할 수 없었다.
- Grok 4.6: 내용은 풍부했지만 토큰 사용량이 매우 컸고, 품질의 뚜렷한 우위는 확인되지 않았다.

## 글 작성 시 주의할 점

- 이번 결과는 특정 PDF, 프롬프트, Cursor usage 집계에 대한 관찰이지 모든 작업의 모델 순위가 아니다.
- `Total Tokens`에는 입력, 캐시, 출력이 함께 포함되므로 순수 토크나이저 효율과 동일하지 않다.
- Auto는 라우팅 모델과 비용을 특정할 수 없으므로 직접 모델 비교 표에서 별도 항목으로 설명해야 한다.
- 트레이딩 전략의 수익성이나 안전성을 검증한 실험이 아니라, 문서 분석 비용과 출력 품질을 비교한 실험이다.
