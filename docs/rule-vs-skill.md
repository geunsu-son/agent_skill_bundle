# Cursor Rule과 Skill의 차이

## 핵심 개념

Cursor에서 **Rule**과 **Skill**은 모두 Agent에게 작업 컨텍스트를 제공하지만, 적용되는 방식과 목적이 다릅니다.

- **Rule**: 작업 중 지속적으로 적용할 선언적 기준과 제약
- **Skill**: 특정 작업이 필요할 때 불러와 실행할 절차적 지식과 도구

> **Rule = 어떻게 판단하고 행동해야 하는가**  
> **Skill = 특정 업무를 어떻게 완료해야 하는가**

Rule을 단순히 “작업자 정의”, Skill을 “업무 절차”라고 이해해도 실무에서는 유용합니다. 다만 엄밀하게는 **내용의 종류보다 적용 범위와 로딩 시점**이 더 중요한 구분 기준입니다.

---

## Rule

Rule은 Agent가 작업할 때 따라야 하는 행동 원칙, 권한, 제약사항, 품질 기준, 프로젝트 관례를 정의합니다.

### 주요 용도

- Agent가 어떤 역할과 관점으로 작업해야 하는지 정의
- 프로젝트 전반에서 반드시 지켜야 하는 원칙 지정
- 허용하거나 금지할 작업 정의
- 코드 스타일과 작성 기준 통일
- 특정 파일이나 디렉터리에 적용할 규칙 지정
- 검증, 보안, 데이터 보호와 같은 공통 품질 기준 정의

### Rule에 적합한 내용

- 여러 업무에서 반복해서 지켜야 하는 기준
- 작업이 달라져도 유지되어야 하는 권한이나 금지사항
- 특정 파일 또는 디렉터리에서 항상 적용되어야 하는 기준
- 결과물의 품질과 안전성을 위한 공통 원칙
- Agent가 판단할 때 계속 참고해야 하는 프로젝트 관례

프로젝트 Rule은 일반적으로 다음 위치에 둡니다.

```text
.cursor/rules/*.mdc
```

---

## Skill

Skill은 반복적으로 수행하는 특정 업무의 절차, 도구 사용법, 스크립트, 템플릿, 참고 자료를 하나의 재사용 가능한 작업 단위로 정의합니다.

### 주요 용도

- 정기 업무 절차 표준화
- 복잡한 작업 순서 재사용
- 검증, 테스트, 배포 절차 정의
- 반복 작업에 필요한 스크립트와 템플릿 제공
- 업무 결과물의 형식과 완료 조건 정의
- 특정 도메인 지식을 필요할 때만 제공

### Skill에 적합한 내용

- 특정 업무를 요청받았을 때만 필요한 내용
- 실행 순서가 결과의 품질에 영향을 주는 다단계 작업
- 테스트, 검증 또는 완료 조건이 존재하는 업무
- 스크립트, 템플릿, 예제, 참고 문서를 함께 제공해야 하는 작업
- 항상 컨텍스트에 포함하면 낭비가 되는 큰 지침

프로젝트 Skill은 일반적으로 다음 위치에 둡니다.

```text
.cursor/skills/<skill-name>/SKILL.md
```

---

## 선택 기준

| 구분 | Rule | Skill |
|---|---|---|
| 핵심 목적 | 판단 및 행동 기준 정의 | 특정 업무의 완료 방법 정의 |
| 성격 | 선언적 지침 | 절차적 지식 |
| 적용 시점 | 작업 전반에 지속 적용 | 관련 작업을 수행할 때 로드 |
| 주요 내용 | 역할, 권한, 제약, 품질 기준 | 단계, 도구, 템플릿, 검증 방법 |
| 대표 질문 | 어떻게 행동해야 하는가? | 이 업무를 어떻게 완료하는가? |

- 반복해서 지켜야 하는 원칙 → **Rule**
- 작업자의 역할과 권한 → **Rule**
- 단계적으로 수행해야 하는 작업 → **Skill**
- 정기 업무나 특정 업무의 실행 절차 → **Skill**
- 스크립트나 템플릿을 포함한 재사용 작업 → **Skill**

---

## 경계가 겹치는 경우

예를 들어 “배포 전 테스트를 수행한다”는 내용은 두 곳 모두에 등장할 수 있습니다.

- Rule: 테스트 없이 배포하지 않는다는 **품질 기준**
- Skill: 어떤 테스트를 어떤 순서로 수행하는지에 대한 **실행 절차**

즉, 공통 원칙은 Rule에 두고 실제 실행법은 Skill로 분리합니다.

---

## 토큰과 실행 효율

Rule은 적용 대상 작업마다 Agent 컨텍스트에 포함될 수 있습니다. 따라서 긴 업무 절차, SQL, Python 코드, 템플릿을 Rule에 직접 작성하면 관련 없는 작업에서도 불필요하게 컨텍스트를 차지할 수 있습니다.

Skill은 관련 업무를 수행할 때만 로드할 수 있으므로 상세 절차와 참고 자료를 Skill로 분리하면 현재 작업에 필요한 내용에 더 집중할 수 있습니다.

권장 구조는 다음과 같습니다.

```text
Rule
→ 공통 원칙, 권한, 안전 기준

Skill
→ 특정 업무의 실행 순서, 입력값, 검증 방법, 완료 조건

Script
→ 반복 실행할 SQL, Python 코드, 자동화 로직
```

반복 실행되는 코드가 길거나 변경 가능성이 높다면 `SKILL.md`에 코드 전문을 넣기보다 별도 스크립트 파일로 관리하는 것이 좋습니다.

- Agent가 매번 같은 코드를 새로 생성할 필요가 줄어듦
- 코드 변경 시 한 파일만 수정하면 됨
- 테스트와 버전 관리가 쉬워짐
- 실행 결과가 더 일관적임
- Skill 문서의 컨텍스트 크기를 줄일 수 있음

> **Rule은 짧게 유지하고, 상세 절차는 Skill로 분리하며, 반복 실행 코드는 Script로 관리합니다.**

---

## 작성 원칙

### Rule

- 하나의 Rule에는 서로 밀접한 기준만 포함
- 항상 필요하지 않으면 적용 조건이나 파일 범위를 제한
- 추상적인 표현보다 관찰 가능한 행동 기준 작성
- 좋은 예시와 금지 패턴을 함께 명시
- 큰 업무 절차 전체를 Rule에 넣지 않음

### Skill

- 해결할 업무와 사용 시점을 명확히 작성
- Agent가 그대로 실행할 수 있는 구체적인 단계 구성
- 사용할 도구와 입력값 명시
- 검증 방법과 완료 조건 포함
- 필요한 스크립트, 템플릿, 예제를 같은 디렉터리에 배치
- 다른 Skill과 책임이 과도하게 겹치지 않도록 범위 제한

---

## 제작 전 체크리스트

1. 여러 작업에 지속적으로 적용해야 하는 기준인지 확인한다.
2. 특정 업무에서만 필요한 절차인지 확인한다.
3. 역할, 권한, 금지사항이면 Rule을 우선한다.
4. 단계, 도구, 템플릿, 검증 과정이면 Skill을 우선한다.
5. 공통 원칙은 Rule에 두고 상세 실행법은 Skill로 분리한다.
6. 반복 가능하고 결정론적인 로직은 Script로 분리한다.

> **Rule은 Agent가 어떤 원칙과 제약 아래 판단해야 하는지 정의하고, Skill은 특정 업무를 어떤 단계와 도구로 완료하고 검증해야 하는지 정의합니다.**
