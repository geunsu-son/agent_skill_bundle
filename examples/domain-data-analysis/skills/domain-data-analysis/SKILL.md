# Domain Data Analysis

## 상태

`testing`. 마케팅·학습 시드와 주문 퍼널·학습 궤적 네 건으로 절차를 검증했습니다. 케이스별 실행 기록은 예시에 두지 않습니다.

## 목적

데이터 분석 요청에서 도메인과 질문을 먼저 고르고, 그에 맞는 기법과 변수 설계를 남긴 뒤, 검증과 비분석가용 해석까지 한 세트로 완료합니다.

## 사용 시점

- 매출·마케팅, 학습, 또는 그와 비슷한 표 형식 데이터 분석
- “이 데이터로 뭐가 보이는지 봐줘”처럼 질문이 넓은 요청
- 모델·차트보다 의사결정에 쓸 해석이 필요한 요청

## 입력

- 분석으로 돕고 싶은 결정 또는 궁금한 점
- 데이터 위치(캐글 URL, 로컬 파일, 컬럼 설명)
- 독자: 임원진 또는 대중. 없으면 해석·보고서 직전에 묻는다. 추측하지 않는다.
- 있으면: 이미 쓰는 지표, 개입 가능한 레버, 보지 말 변수

질문이 없으면 Agent가 데이터만 보고 질문을 만들지 않습니다. 가능한 질문 후보를 제시하고 하나를 가정으로 명시합니다.

## 절차

### 1. 질문·도메인·독자 확정

한 문장씩 적습니다.

- 누가 어떤 결정을 하려는가
- 분석 단위는 무엇인가 (고객, 주문, 세션, 학생, 주차, 콘텐츠)
- 1차 독자는 임원진인가 대중인가. 요청에 없으면 여기서 고르지 않고, 해석·보고서 직전 gate에서 묻습니다.

도메인을 마케팅/학습 등으로 이름 붙이되, 이름보다 질문과 단위를 우선합니다.

### 2. 질문 유형으로 기법 후보 열기

아래 표에서 질문과 가장 가까운 행을 고릅니다. 여러 행이 같으면 의사결정에 더 가까운 쪽을 택합니다.

| 질문 유형 | 우선 검토 기법 |
|---|---|
| 어디서 빠지거나 막히는가 | 퍼널, 단계별 전환, drop-off |
| 누가 또는 어느 집단이 결과를 만드는가 | 세그먼트, 코호트, 기여 분해 |
| 어떤 변수가 결과에 영향을 주는가 | 드라이버 분석, 대조, 부분 의존 |
| 개체가 시간에 따라 어떻게 바뀌는가 | 개인/계정 궤적, 잔존·이탈 |
| 다음에 무엇이 일어날 것 같은가 | 예측 + 해석. 예측만으로 종료하지 않음 |
| 무엇을 바꾸면 결과가 달라질 것 같은가 | 개입 시나리오, 민감도, 실험 설계 |

시드 도메인에서 자주 열리는 후보:

- **매출·마케팅**: 퍼널, 세그먼트/RFM, 코호트, 채널·상품 기여. 매출을 늘리려면 “어디서 빠지는가”와 “어떤 고객이 매출을 만드는가”를 먼저 가릅니다.
- **학습**: 성과 드라이버, 개인 학습 궤적, 이탈·미완료. 점수 예측보다 “무엇을 바꾸면 학습이 달라지는가”를 우선합니다.

도메인 카드는 후보를 떠올리는 힌트일 뿐, 체크리스트가 아닙니다.

### 3. 데이터 입도로 불가능한 기법 걸러내기

스키마를 보고 분석 단위, 시간 축, 단계(퍼널) 존재 여부, 개체 식별키를 확인합니다.

- 단계가 없으면 퍼널을 하지 않습니다. `order_status`처럼 현재 상태 하나만 있는 컬럼은 단계 로그가 아닐 수 있습니다. 승인·출고·배송 시각처럼 순서를 재구성할 수 있을 때만 퍼널로 채택합니다.
- 반복 관측이 없으면 궤적·코호트를 하지 않습니다.
- 개체 키가 없으면 개인 추적을 하지 않습니다. 이름이 `customer_id`여도 주문마다 새로 발급되면 고객 단위가 아닙니다.

탈락한 기법과 이유를 설계 메모에 남깁니다. 그다음 남은 후보 중 질문에 가장 가까운 기법을 채택합니다.

### 4. 종속변수 탐색

채택 기법의 결과 변수를 정의합니다.

- 이름, 계산식, 기간, 단위
- 합계 / 평균 / 중앙값 / 비율 / 인당 중 무엇인지
- 결측, 0, 이상치, 환불·취소를 어떻게 다루는지
- 의사결정 단위와 정의가 맞는지 (예: 주문 매출 vs 고객 LTV)

한 줄 요약으로 끝내지 않습니다. 정의가 바뀌면 결론이 바뀌는 지점을 적습니다.

### 5. 설명변수 탐색

후보 변수를 세 묶음으로 나눕니다.

1. **개입 가능**: 캠페인, 콘텐츠 노출, 과제 횟수처럼 실제로 바꿀 수 있는 것
2. **맥락**: 시기, 지역, 선행 실력처럼 해석에 필요하지만 당장 못 바꾸는 것
3. **누수·위험**: 결과 이후에 생기는 값, 타깃 재정의에 가까운 값(이탈하면 과제 수가 줄어드는 것), 식별 가능한 개인 속성

상관·중요도를 보기 전에 이 분류를 끝냅니다. 개입 가능 변수가 없으면 예측 모델보다 현황 진단이 맞을 수 있습니다. 그 판단을 적습니다.

### 6. 분석 설계 메모 작성

분석을 실행하기 **전에** 아래를 채웁니다.

```md
## 분석 설계 메모

- 질문:
- 도메인 / 분석 단위:
- 독자:
- 채택 기법:
- 탈락 기법과 이유:
- 종속변수:
- 설명변수 (개입 / 맥락 / 제외):
- 비교 대상(베이스라인):
- 검증 방법:
- 이번엔 하지 않을 것:
- 가정:
```

이 메모가 없으면 다음 단계로 가지 않습니다.

### 7. 분석 실행과 검증

설계한 기법만 실행합니다. 흥미 위주 EDA로 범위를 넓히지 않습니다.

검증은 데이터에 맞는 것을 고릅니다.

- 시간이 있으면 최근 구간을 홀드아웃하거나 기간을 나눠 같은 패턴이 남는지 봅니다.
- 세그먼트가 있으면 상위 집단 패턴이 다른 집단에서도 보이는지 봅니다.
- 예측이면 학습에 쓸 수 없는 시점 정보가 섞였는지(누수)를 확인합니다.
- 항상 베이스라인과 비교합니다.

버틴 결과와 깨진 결과를 구분합니다. 깨진 패턴은 보고서에서 내립니다.

### 8. 독자 gate

해석과 보고서를 쓰기 **전에** 1차 독자를 확인합니다. 요청에 이미 `임원진` 또는 `대중`이 있으면 그대로 씁니다. 없으면 아래를 묻고, 답이 오기 전에 이후 단계를 진행하지 않습니다.

```text
이번 해석·보고서의 1차 독자는 누구인가요?
1. 임원진 — 결정할 내용, 효과 크기, 다음 행동
2. 대중 — 소개·보도. 컬럼명·홀드아웃 없이 한두 문장
```

둘 다이면 각각 한 벌을 씁니다. 추측으로 고르지 않습니다.

### 9. 강조점과 표현 고르기

독자 gate에서 고른 쪽에 맞춰 본문에 올릴 것과 내릴 것을 고릅니다.

| 독자 | 강조 | 표현 |
|---|---|---|
| 임원진 | 한 가지 결정, 효과 크기, 확신의 한계, 다음 액션 1~2개 | 원, %, 명, 기간. 모델 지표는 부록 |
| 대중 | 무엇이 얼마만큼인지, 그래서 무엇을 하면 되는지 | 홀드아웃·컬럼명·상태코드·근거 등급을 빼고 한두 문장 |

같은 숫자를 독자에게 맞게 다시 씁니다. 분석가 사이에서만 통하는 말을 본문에 두지 않습니다.

### 10. 보고서 작성

아래 형식을 기본으로 합니다.

```md
## 한눈에 보기

- 결정 또는 질문:
- 핵심 결과: 독자 단위로 1~2문장
- 근거 강도: 강함 / 중간 / 약함 (검증에서 버틴 정도)
- 다음에 할 일: 1~2개

## 무엇을 봤는가

사실만. 채택 기법과 종속변수 정의에 해당하는 결과.

## 그것이 뜻하는 바

추정과 해석. 개입 가능한 지점을 우선한다.

## 한계

하지 못한 기법, 깨진 패턴, 인과로 말할 수 없는 부분.

## 다음에 확인할 것

데이터·실험·현장 확인 중 실제로 가능한 항목만.
```

분석가용 상세(코드, 지표, 차트 해석)는 요청이 있을 때만 부록으로 붙입니다.

## 완료 조건

- 질문, 도메인, 독자가 명시됨. 독자는 묻거나 요청에서 확인한 임원진 또는 대중
- 채택 기법과 탈락 이유가 있음
- 종속변수·설명변수 탐색이 설계 메모에 남아 있음
- 설계 메모 이후에 분석이 실행됨
- 검증과 베이스라인 비교가 있음
- 독자 gate 이후에 해석·보고서가 작성됨
- 보고서 본문이 지정 독자 단위로 작성됨. 대중이면 한눈에 보기에 컬럼명·홀드아웃·상태코드가 없음
- 사실 / 추정 / 권고가 구분됨
- 개인 식별 기록이 본문에 없음

## 실패로 보는 결과

- 컬럼 프로파일링과 모델 점수가 보고서의 앞부분을 차지함
- 마케팅이면 무조건 퍼널, 학습이면 무조건 예측처럼 도메인 고정 기법을 씀
- 데이터에 없는 퍼널·궤적을 만들어 냄
- 검증 없이 전체 데이터 적합 결과를 일반화함
- 독자(임원진/대중)를 묻지 않고 해석·보고서를 씀

## 향후 Script 후보

- 스키마·입도 점검(단위 키, 시간 축, 단계 여부)
- 결측·이상치·기간 분할의 반복 전처리
- 설계 메모·보고서 템플릿 채우기

캐글 사이트 자체는 이 환경에서 내려받지 못했고, 동일 공개본은 UCI·GitHub 미러로 실행했다. 다운로드 코드를 공통 Script로 두기에는 출처가 케이스마다 달랐다. 입도 점검은 네 번 모두 같은 질문이라 다음 후보로 남긴다.
