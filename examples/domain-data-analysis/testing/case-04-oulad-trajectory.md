# Case 04 — 추가 / 학습 궤적·이탈

캐글: [thedevastator/open-university-learning-analytics-dataset](https://www.kaggle.com/datasets/thedevastator/open-university-learning-analytics-dataset)  
입수: UCI OULAD `studentInfo.csv`(32,593 등록), `studentAssessment.csv`. 클릭 로그 `studentVle`(약 433MB)는 이번 질문에 필수가 아니어서 제외.

시드 2는 단면이라 개인 추적이 탈락했다. 반복 과제 기록이 있으면 궤적이 채택되는지 보기 위한 케이스다.

## 분석 설계 메모

- 질문: 개인 학습 기록으로 이탈을 언제 먼저 볼 수 있는가
- 도메인 / 분석 단위: 학습 / 모듈 등록(학생×기수)
- 독자: 학습 지원 담당자
- 채택 기법: 조기 과제 점수와 이탈 여부. 개인당 평균 7회 과제 제출이 있어 궤적이 가능
- 탈락 기법과 이유: 클릭 스트림 퍼널 — 이번엔 VLE 로그를 쓰지 않음. 최종 점수 예측 모델 — 예측 정확도보다 조기 신호가 질문
- 종속변수: 최종 결과가 Withdrawn인지. 통과(Pass/Distinction)는 보조
- 설명변수 (개입 / 맥락 / 제외): 개입 후보 — 첫 과제 저조 시 지원. 맥락 — 기수(`code_presentation`). 누수 — 총 과제 제출 수(이탈하면 제출이 줄어 결과를 재정의함)
- 비교 대상(베이스라인): 전체 이탈 31.2%
- 검증 방법: 2013B/J, 2014B/J 네 기수에서 과제 없음·첫 점수 낮음 패턴이 남는지
- 이번엔 하지 않을 것: 제출 횟수를 늘리라는 처방, 인구통계를 바꿀 레버로 쓰기
- 가정: 은행 인정 점수(`is_banked=1`)는 제외. 등록 단위가 분석 단위다(한 학생이 여러 기수 가능)

## 한눈에 보기

- 결정 또는 질문: 누가 이탈 위험이 높은지 언제 개입 목록에 올릴 것인가
- 핵심 결과: 과제를 한 번도 내지 않은 등록의 79%가 이탈한다. 과제를 낸 등록은 21%다. 첫 과제가 40점 이하면 이탈 36%, 81점 이상이면 16%다.
- 근거 강도: 중간 이상 — 네 기수 모두 “과제 없음 → 이탈 73–88%”가 반복된다. 첫 점수 낮음은 기수마다 30–48%로 크기는 달라진다.
- 다음에 할 일: 첫 과제 미제출·저조 학생을 조기 지원 목록의 1순위로 둔다. 총 제출 횟수는 개입 목표로 쓰지 않는다.

## 무엇을 봤는가

- 학생 키와 반복 과제가 있어 궤적을 채택했다.
- 과제 없음 5,908건 이탈 79.0%, 과제 있음 26,685건 이탈 20.6%. 전체 31.2%보다 과제 없음이 훨씬 높다.
- 첫 점수 ≤40 이탈 36.4% / 통과 35.7%. 첫 점수 81–100 이탈 15.5% / 통과 70.3%.
- 제출 1–2회 이탈 56.4%처럼 보이지만, 이탈하면 이후 과제를 안 내므로 이 숫자는 원인과 결과가 섞여 있다.
- 2013B·2013J·2014B·2014J 모두 과제 없음 이탈이 70%대 후반~80%대다.

## 그것이 뜻하는 바

추정: 개인 기록이 있을 때는 “어떤 배경이 점수를 설명하는가”보다, 과정 초반에 과제를 냈는지·첫 점수가 낮은지가 지원 시점을 가른다. 제출 횟수를 늘리라는 말은 이탈의 정의를 다시 말하는 것에 가깝다.

## 한계

- 과제 미제출이 이탈의 원인인지, 이미 그만둔 결과인지는 이 표만으로 가르지 못한다.
- VLE 클릭을 안 써서 콘텐츠 단위 개입은 말할 수 없다.
- 인구통계 격차는 이번 권고에 넣지 않았다.

## 다음에 확인할 것

- 필요하면 VLE 클릭으로 과제 이전의 접속 단절을 볼지
