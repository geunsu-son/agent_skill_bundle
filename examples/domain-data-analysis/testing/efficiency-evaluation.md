# 효율 평가

네 건의 실행 기록만으로 판단한다. Rule·Skill을 끈 대조 실행은 없어서, **시간(분)** 단축은 주장하지 않는다. 대신 같은 질문에서 흔한 Agent 경로(요약 통계 → 상관 → 모델 → 차트)와 비교해 과정이 줄었는지 본다.

등급: `충족` / `부분` / `미흡` / `미검증`

## 종합

| 기준 | 등급 | 한 줄 |
|---|---|---|
| 1. 유효한 분석까지의 시간과 과정 | 부분 | 잘못된 우회는 줄었고, 앞단 설계는 늘었다. 시계 비교는 없음 |
| 2. 의도대로 기법 선정 | 충족 | 4/4가 질문·입도에 맞게 갈림. 도메인 이름만으로는 갈리지 않음 |
| 3. 대중 소개 형태 | 부분 | 임원용 본문은 됨. 첫 산출물은 대중이 그대로 쓰기에 용어가 남음 |
| 4. 오탐 억제 (추가) | 충족 | 없는 퍼널, 단면 궤적, 예측 점수, 누수 레버를 본 결론에서 뺌 |
| 5. 검증이 과장을 내림 (추가) | 부분 | 네 건 모두 검증함. 결론을 뒤집기보다 강도를 낮춤 |
| 6. 독자 레이어 분리 (추가) | 미흡→부분 | 임원/실무는 있음. 대중 문장은 평가 시점에 없어 보강함 |

**결론:** 효율의 핵심은 속도가 아니라 **유효한 분석을 더 짧게 고르는 것**이었다. 그 점은 네 건에서 확인된다. 대중 소개는 의도만 있고 첫 보고서에는 덜 닫혀 있었다.

## 1. 유효한 분석을 도출하기까지의 시간과 과정

묻는 것: 차트·모델을 더 빨리 냈는가가 아니라, **의사결정에 쓸 수 있는 분석**까지 우회가 줄었는가.

단축된 과정 (사실):

- 케이스 1: 단계 없는 거래 데이터에서 퍼널을 만들지 않음
- 케이스 2: 점수 예측 모델·accuracy를 본문에 두지 않음
- 케이스 4: 질문에 필요 없는 VLE 클릭 로그(약 433MB)를 제외
- 네 건 모두 전체 컬럼 프로파일 대신 개입/맥락/누수만 나눔
- 설계 메모의 탈락 이유가 보고서 한계 칸으로 거의 그대로 감

늘어난 과정 (사실):

- 분석 전에 설계 메모를 채움 (Skill 1–6)
- 케이스 3은 실행 중에 “상태 컬럼 ≠ 퍼널” 규칙을 보강함
- 케이스 4는 제출 횟수 누수를 설계에서 완전히 막지 못하고 실행 중 제외함

판단: **부분**. 유효한 결론까지의 *잘못된 분기*는 줄었다. 숙련된 분석가가 이미 같은 판단을 한다면 앞단 메모는 overhead다. 이 저장소의 문제 정의는 “Agent가 범용 EDA로 들어간다”이므로, 그 경로 대비로는 과정이 짧다. 분 단위 단축은 **미검증**.

## 2. 설계한 의도대로 분석 기법을 선정했는가

원래 의도: 도메인마다 기법이 다르다. 매출은 퍼널 또는 세그먼트, 학습은 드라이버 또는 개인 추적. 질문과 입도가 기법을 고른다.

| 케이스 | 의도한 분기 | 실제 채택 | 일치 |
|---|---|---|---|
| 1 거래 매출 | 세그먼트, 퍼널 탈락 | 고객 기여 분해 | 예 |
| 2 시험 점수 | 드라이버, 궤적 탈락 | 집단 차이 + 층화 | 예 |
| 3 주문 이행 | 같은 커머스라도 퍼널 | 타임스탬프 퍼널 | 예 |
| 4 학습 이탈 | 같은 학습이라도 궤적 | 조기 점수·미제출 | 예 |

도메인 카드(마케팅/학습)만 보면 1과 3, 2와 4를 구분하지 못한다. 실제 선정 장치는 도메인 백과사전이 아니라 **질문 유형 표 + 입도 필터**였다. 이는 처음 설계와 같다.

빈틈: 케이스 3의 상태값 함정, 케이스 4의 누수 변수는 초안 Skill에 없었다. 기법은 맞았고, 함정은 실행 후 Rule에 반영했다.

판단: **충족**.

## 3. 대중에게 소개될 수 있는 형태인가

Skill이 1차로 정한 독자는 임원·실무 의사결정자다. “대중”은 그보다 넓은 소개·보도·소비자 독자다.

임원용으로 된 것:

- 한눈에 보기에 결정, 크기(%, 점, 건), 다음 행동
- 모델 지표가 본문 앞에 없음
- 사실 / 추정 / 한계가 칸으로 나뉨

대중이 그대로 쓰기 어려웠던 것 (첫 산출물):

- `홀드아웃`, `근거 강도: 중간`, `CustomerID`, `processing/invoiced`, `code_presentation`
- 케이스 3의 “약 37만”은 통화가 없어 오해 가능
- 소비자·학습자 문장을 같은 숫자에 한 번 더 쓰는 실험은 평가 전까지 하지 않음

판단: **부분**. 분석가 노트북보다는 소개 가능하고, 기사·안내문 초고로는 한 번 더 번역이 필요했다. 아래 대중용 한 줄을 각 케이스에 보강해 이 칸을 닫기 시작했다.

## 추가 기준 (추천해 평가에 포함)

제안 기준 3가지는 속도와 선정과 표현이다. 이 예시의 목적에는 다음이 빠져 있으면 효율을 과대평가하기 쉽다.

### 4. 오탐 억제 — 잘못된 분석을 시작하지 않았는가

시간을 줄이는 주된 장치가 “빨리 계산”이 아니라 “안 해도 되는 분석을 안 하는 것”이다.

- 없는 단계로 퍼널을 만들지 않음 (1)
- 단면 데이터로 개인 추적을 주장하지 않음 (2)
- 사람 키가 아닌 `customer_id`로 세그먼트하지 않음 (3)
- 제출 횟수를 이탈 개입 목표로 올리지 않음 (4)

판단: **충족**. 1번 기준의 실체다.

### 5. 검증이 과장을 내렸는가

빠른 오답은 효율이 아니다.

- 1: 상위 20% 기여 72% → 이후 기간 55%로 강도 하향
- 2: 준비 과정 차이 8.5점 → 30% 구간 5.5점
- 3: 2016년(329건)을 본 결론에서 제외
- 4: 네 기수에서 과제 없음 이탈이 반복됨을 확인

판단: **부분**. 검증은 네 건 모두 있다. 대부분 결론을 뒤집지 않고 확신만 낮췄다. 그 자체는 실패가 아니다.

### 6. 독자 레이어가 나뉘는가

임원 문장과 대중 문장은 같은 템플릿으로 안 끝난다. 첫 보고서는 임원 칸에 가깝고, 대중 칸은 비어 있었다. 평가 후 각 케이스에 대중용 한 줄을 붙였다.

판단: 평가 시점 **미흡**, 보강 후 **부분**. 아직 별도 소비자 안내문을 쓰진 않았다.

쓰지 않은 후보: 분 단위 런타임, 다른 Agent와의  Blind 비교. 측정이 없어 등급을 주지 않는다.
