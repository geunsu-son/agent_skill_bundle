# Case 03 — 추가 / 주문 이행 퍼널

캐글: [olistbr/brazilian-ecommerce](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)  
입수: GitHub `olist_orders_dataset.csv` (99,441주문), `olist_order_items_dataset.csv`

시드 1과 같은 커머스라도, 질문이 “누가 매출을 만드는가”가 아니라 “어디서 막히는가”이고 단계 시각이 있으면 퍼널이 채택되는지 보기 위한 케이스다.

## 분석 설계 메모

- 질문: 주문이 구매 이후 어느 단계에서 가장 많이 멈추는가
- 도메인 / 분석 단위: 커머스 운영 / 주문
- 독자: 운영·물류 책임자
- 채택 기법: 타임스탬프로 재구성한 단계 퍼널
- 탈락 기법과 이유: `order_status` 값 나열만으로 퍼널 — 이 컬럼은 현재 상태 하나다. 고객 세그먼트 — `customer_id`는 주문마다 새로 발급되어 사람 키가 아님(`customer_unique_id`가 사람)
- 종속변수: 각 단계 도달 비율. 단계 = 구매 시각 → 승인 시각 → 운송사 인계 시각 → 고객 배송 시각
- 설명변수 (개입 / 맥락 / 제외): 개입 — 승인 이후 출고, 출고 이후 배송 완료. 맥락 — 연도. 제외 — 상품 리뷰 점수(결과 이후)
- 비교 대상(베이스라인): 전체 배송 완료율 97.0%
- 검증 방법: 2017년과 2018년을 나눠 같은 병목인지 본다. 2016년은 주문 329건이라 본 결론에 쓰지 않는다
- 이번엔 하지 않을 것: 고객 LTV 세그먼트, 리뷰 예측
- 가정: 시각이 비어 있으면 그 단계에 도달하지 않았다고 본다

## 한눈에 보기

- 결정 또는 질문: 미배송을 줄이려면 어느 구간을 먼저 볼 것인가
- 핵심 결과: 구매의 97%는 고객에게 도착한다. 가장 큰 하락은 승인 후 운송사 인계(1.6%p)이고, 그다음이 인계 후 고객 도착(1.2%p)이다. 미도착 주문 2,965건의 상품 금액은 약 37만이다.
- 근거 강도: 중간 이상 — 2017·2018년 모두 승인율은 99.8%로 높고, 배송 완료는 96.3% / 97.7%다. 2016년은 표본이 작아 제외했다.
- 다음에 할 일: 출고 대기(`processing`/`invoiced`)와 이미 출고됐지만 미도착(`shipped` 1,107건)을 나눠 본다. 고객 세그먼트는 `customer_unique_id`로 다시 설계한다.

## 대중용 한 줄

산 물건은 백 건 중 아흔일곱 건이 집에 도착합니다. 결제가 막히기보다, 출고와 배송 중에 일부가 멈춥니다. 주문이 크게 실패한다고 보기엔 완료율이 이미 높고, 남은 문제는 출발 전 대기와 출발 후 미도착입니다.

## 무엇을 봤는가

- 상태 분포는 delivered 96,478로 한쪽으로 치우쳐 있어, 상태 값만 보면 퍼널처럼 보이지 않는다.
- 시각으로 재구성하면 구매 100% → 승인 99.8% → 운송사 인계 98.2% → 고객 도착 97.0%다.
- 파이프라인에 남은 주문 1,729건 중 shipped 1,107, invoiced 314, processing 301이다. 취소·불가 1,234건은 별도다.
- 2017·2018년 취소·불가 비율은 1.6%, 0.9%로 낮다.

## 그것이 뜻하는 바

추정: 결제 승인 자체는 거의 병목이 아니다. 손댈 곳은 승인 후 출고와, 출고 후 미도착이다. 전체 완료율이 이미 97%라서 “퍼널이 무너졌다”고 말하면 과장이다. 금액 기준으로는 도착 매출 약 1,322만 대비 미도착 37만이다.

## 한계

- 왜 출고·배송이 멈췄는지는 이 테이블만으로 모른다.
- `customer_id`로 재구매 세그먼트를 하면 사람 수가 부풀려진다.
- 이벤트 로그형 view→cart→purchase는 이 데이터에 없다.
