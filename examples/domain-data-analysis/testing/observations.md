# 관찰

네 번 실행 후. 예시는 정답이 아니라 검증 대상이다.

## 바로 도움이 된 내용

- 질문과 입도를 먼저 고정하니, 같은 커머스라도 케이스 1은 세그먼트, 케이스 3은 퍼널이 나왔다. 학습도 단면(케이스 2)과 반복 과제(케이스 4)에서 기법이 갈렸다.
- “없는 퍼널을 만들지 말 것”이 케이스 1을 지켰다.
- 설계 메모의 탈락 이유가 보고서 한계 칸을 거의 그대로 채웠다.
- 비분석가 단위(%, 점, 건)로 쓰니 모델 지표가 본문에 올라오지 않았다.

## 불필요하거나 과도했던 내용

- 캐글 사이트에서 파일을 직접 받는 절차는 이 환경에서 불가능했다. 데이터셋 선정은 캐글 검색으로 충분했고, 다운로드는 미러가 필요했다.
- 도메인 카드를 더 늘릴 필요는 아직 없었다. 질문 유형 표 + 입도 필터로 네 케이스가 갈렸다.
- 케이스 3에서 상태값 분포만 보면 퍼널이 아닌 것처럼 보여, 타임스탬프 재구성 규칙이 Skill에 없었다. 실행 중에 규칙을 보강했다.
- 케이스 4의 제출 횟수는 중요해 보이지만 이탈의 재정의였다. 누수 구분이 설계 단계에 더 밝히 있어야 했다.

## 다음 실행에서 바꿀 한 가지

입도 점검에 다음을 기본 질문으로 넣는다. (이미 Rule·Skill에 반영함)

1. 상태 컬럼이 이벤트 로그인가, 현재 값 하나인가?
2. ID 이름이 사람 단위인가, 거래마다 새로 나오나?
3. 이 변수가 결과보다 시간상 앞서는가?

## 관찰 항목별

| 항목 | 결과 |
|---|---|
| 도메인 판단이 기법을 바꿨는가 | 이름보다 질문·입도가 바꿨다. 마케팅/학습 레이블만으로는 1과 3, 2와 4를 구분하지 못한다 |
| 입도 필터가 불가능한 분석을 막았는가 | 케이스 1 퍼널, 케이스 2 궤적을 막음. 케이스 3은 상태≠퍼널을 한 번 더 걸러야 했음 |
| 변수 탐색이 과했는가 | 컬럼 전체를 프로파일하지 않고 개입/맥락/누수만 나눠도 충분했음 |
| 검증이 결론을 바꿨는가 | 케이스 1 기여 72%→홀드아웃 55%로 강도만 낮춤. 케이스 2 효과 8.5→5.5. 케이스 3은 2016년을 제외 |
| 보고서가 재해석 없이 읽히는가 | 본문은 결정·크기·다음 행동 위주. 분석가 상세는 넣지 않음 |
| 시드 외 카드가 필요했는가 | 아니요. 추가 2건은 같은 표로 처리됨 |

## 효율 평가 (사용자 기준)

상세: [`efficiency-evaluation.md`](efficiency-evaluation.md)

1. 과정 단축 — **부분**. 잘못된 우회는 줄고 앞단 설계는 늘음. 분 단위는 미검증
2. 기법 선정 — **충족**. 4/4가 질문·입도에 맞게 갈림
3. 대중 표현 — **부분**. 임원용은 됨. 대중 한 줄은 평가 후 보강
4. 오탐 억제 — **충족**
5. 검증이 과장을 내림 — **부분**
6. 독자 레이어 분리 — 평가 시점 미흡, 보강 후 부분

## 아직 검증하지 않은 것 (추후 과제)

- view→cart→purchase 이벤트 로그. 캐글 REES46 계열은 파일이 크고 이 환경에서 원본을 받지 못했다.
- Skill 없이 같은 질문을 맡겨 우회가 실제로 줄는지 대조
- `.cursor/` 승격. 반복 사용 전이다.
