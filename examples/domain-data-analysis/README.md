# Domain Data Analysis — ver0 Example

데이터 분석을 맡겼을 때 Agent가 곧바로 범용 EDA·모델로 들어가지 않고, **도메인과 질문과 데이터 입도에 맞는 기법을 고른 뒤** 설계·검증·의사결정자용 해석까지 가게 하는 예시입니다.

완성된 분석 프레임워크가 아닙니다. 마케팅과 학습 두 시드로 Rule·Skill 분리가 실제로 도움이 되는지 보기 위한 `draft`입니다.

## 해결하려는 문제

분석을 요청하면 흔히 같은 순서가 반복됩니다.

1. 컬럼 요약과 상관
2. 모델 학습
3. 차트와 지표 나열

그러면 매출 증대인지, 학습 성과인지와 무관하게 같은 산출물이 나옵니다. 퍼널·세그먼트·드라이버·개인 추적처럼 질문에 맞는 기법은 늦게 붙거나 빠집니다. 보고서는 분석가끼리 보기에는 풍부해도, 임원이나 사용자에게는 다시 번역이 필요합니다.

이 예시는 다음을 먼저 고정하는 것을 목표로 합니다.

1. 무엇을 결정하기 위한 분석인가?
2. 그 질문에 어떤 기법이 후보이고, 데이터 입도상 무엇이 불가능한가?
3. 종속변수와 설명변수를 얼마나 구체적으로 정의했는가?
4. 그 설계가 다른 기간·집단에서도 버티는가?
5. 독자에게 무엇을 강조하고 어떤 단위로 말할 것인가?

## 구성

```text
Rule
→ 기법 선택, 변수 탐색, 검증, 보고에서 계속 지킬 원칙

Skill
→ 질문 확정부터 설계 메모, 실행, 검증, 보고서까지의 절차
```

- [`rules/domain-data-analysis.mdc`](rules/domain-data-analysis.mdc)
- [`skills/domain-data-analysis/SKILL.md`](skills/domain-data-analysis/SKILL.md)

Automation은 두지 않습니다. 분석 요청이 있을 때 실행합니다. Script는 캐글 로드·전처리가 반복되기 전에는 후보만 Skill에 적습니다.

## 시드 도메인

사용자가 든 예시를 첫 시험 범위로 둡니다. 다른 도메인 카드는 이 두 건을 실행해본 뒤에만 늘립니다.

| 도메인 | 자주 열리는 질문 | 기법 후보 | 데이터가 없으면 하지 말 것 |
|---|---|---|---|
| 매출·마케팅 | 어디서 전환이 깨지는가 / 어떤 고객이 매출을 만드는가 | 퍼널, 세그먼트, 코호트, 기여 분해 | 단계 없는 퍼널, 식별키 없는 고객 추적 |
| 학습 | 어떤 변수가 성과에 영향을 주는가 / 개인 기록 추적이 의미 있는가 | 드라이버, 궤적, 이탈 | 단면 데이터에서의 개인 궤적, 점수 예측만으로 결론 |

## 캐글로 시험하는 방법

사내 데이터가 없어도 Skill 절차를 한 바퀴 돌릴 수 있게, 입도가 다른 공개 데이터 두 건을 첫 시험으로 둡니다. 이 저장소에 데이터 파일을 넣지 않습니다.

### 1) 매출·마케팅

- 데이터: [E-Commerce Data](https://www.kaggle.com/datasets/carrie1/ecommerce-data) (UCI Online Retail)
- 가정할 질문: 매출을 늘리려면 어떤 고객 집단부터 볼 것인가
- 기대: 거래 데이터이므로 세그먼트·기여가 퍼널보다 먼저 채택됨. Invoice/Customer 단위와 취소·반품 처리가 종속변수 탐색에 남음
- 실패로 볼 신호: 페이지 단계가 없는데 퍼널을 만들거나, RFM 점수만 보고 임원 문장을 쓰지 않음

### 2) 학습

- 데이터: [Students Performance in Exams](https://www.kaggle.com/datasets/spscientist/students-performance-in-exams)
- 가정할 질문: 시험 점수에 영향을 주는 요인 중 개입 가능한 것은 무엇인가
- 기대: 드라이버 분석이 채택되고, 한 행이 학생 1명인 단면이므로 개인 학습 기록 추적은 탈락으로 명시됨
- 실패로 볼 신호: accuracy를 한눈에 보기에 두거나, 부모 학력 등을 바로 바꿀 레버처럼 권고함

실행 시 출력은 Skill의 설계 메모와 보고서 골격을 그대로 사용합니다. 관찰은 아래 항목으로 `workshop/domain-data-analysis.md`에 되돌립니다.

## ver0에서 일부러 하지 않은 것

- 모든 도메인의 기법 백과사전
- 공통 분석 런타임이나 캐글 다운로드 스크립트
- 자동 모델 선정, AutoML, 대시보드
- 분석가용 노트북 템플릿을 본 산출물로 두기
- `.cursor/` 공통 Rule·Skill로 승격

한두 번 캐글 실행에서 같은 전처리가 반복되고, 설계 메모가 실제로 보고서 품질을 바꿨을 때만 다음 단계를 검토합니다.

## 관찰할 항목

1. 도메인 판단이 기법 선택을 실제로 바꿨는가, 아니면 이름만 붙었는가
2. 데이터 입도 필터가 불가능한 분석을 막아 주었는가
3. 종속·설명변수 탐색이 과했는가, 부족했는가
4. 검증 단계가 결론을 줄이거나 바꿨는가
5. 보고서가 임원·실무자가 다시 해석하지 않아도 되는가
6. 시드 두 도메인 외에 카드가 당장 필요했는가

기본 회고 세 가지도 남깁니다.

1. 바로 도움이 된 내용
2. 불필요하거나 과도했던 내용
3. 다음 실행에서 바꿀 한 가지

## 예시 출력 골격

```md
## 분석 설계 메모

- 질문: 매출을 늘리려면 어떤 고객 집단부터 볼 것인가
- 도메인 / 분석 단위: 마케팅 / 고객
- 독자: 마케팅 임원
- 채택 기법: 고객 세그먼트와 매출 기여 분해
- 탈락 기법과 이유: 퍼널 — 페이지·단계 컬럼 없음
- 종속변수: 최근 12개월 순매출(취소 제외), 고객당
- 설명변수: 구매 빈도·최근성·상품군 (개입: 캠페인 대상 선정 / 맥락: 국가 / 제외: 고객 실명)
- 비교 대상: 전체 고객 평균 매출
- 검증 방법: 최근 3개월을 홀드아웃해 기여 순위가 유지되는지
- 이번엔 하지 않을 것: 이탈 예측 모델
- 가정: CustomerID 있는 행만 고객 단위로 본다

## 한눈에 보기

- 결정 또는 질문: 다음 캠페인 대상을 어디에 둘 것인가
- 핵심 결과: 상위 20% 고객이 순매출의 약 N%를 만든다. 최근성보다 반복 구매 쪽이 기여가 크다.
- 근거 강도: 중간 — 최근 3개월에도 순위는 유지, 국가별로 비율은 달라짐
- 다음에 할 일: 반복 구매 고객 유지 캠페인을 먼저 설계하고, 1회 구매 고객은 별도 실험
```

> 이 예시는 정답 분석 기법을 자동으로 고르는 시스템이 아니라, Agent가 분석 설계를 건너뛰지 않게 만드는 보조 도구입니다.
