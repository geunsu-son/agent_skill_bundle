# Domain Data Analysis — ver0 Example

데이터 분석을 맡겼을 때 Agent가 곧바로 범용 EDA·모델로 들어가지 않고, **도메인과 질문과 데이터 입도에 맞는 기법을 고른 뒤** 설계·검증·해석까지 가게 하는 예시입니다.

완성된 분석 프레임워크가 아닙니다. Rule·Skill 분리를 캐글 공개 데이터 4건으로 시험한 `testing` 예시입니다. 케이스별 실행 기록은 예시에 두지 않습니다.

## 해결하려는 문제

분석을 요청하면 흔히 같은 순서가 반복됩니다.

1. 컬럼 요약과 상관
2. 모델 학습
3. 차트와 지표 나열

그러면 매출 증대인지, 학습 성과인지와 무관하게 같은 산출물이 나옵니다. 퍼널·세그먼트·드라이버·개인 추적처럼 질문에 맞는 기법은 늦게 붙거나 빠집니다. 보고서는 분석가끼리 보기에는 풍부해도, 임원이나 사용자에게는 다시 번역이 필요합니다.

이 예시는 다음을 먼저 고정하는 것을 목표로 합니다.

1. 무엇을 결정하기 위한 분석인가?
2. 그 질문에 어떤 기법이 후보이고, 데이터 입도상 무엇이 불가능한가?
3. 종속변수와 설명변수를 얼마나 구체적으로 정의했는가?
4. 그 설계가 다른 기간·집단에서도 버티는가?
5. 독자(임원진/대중)에게 무엇을 강조하고 어떤 단위로 말할 것인가?

## 구성

```text
Rule
→ 기법 선택, 변수 탐색, 검증, 보고에서 계속 지킬 원칙

Skill
→ 질문 확정부터 설계 메모, 실행, 검증, 독자 gate, 보고서까지의 절차
```

- [`rules/domain-data-analysis.mdc`](rules/domain-data-analysis.mdc)
- [`skills/domain-data-analysis/SKILL.md`](skills/domain-data-analysis/SKILL.md)

Automation은 두지 않습니다. 해석·보고서는 임원진 또는 대중인지 확인된 뒤에만 씁니다.

## 시드 도메인

| 도메인 | 자주 열리는 질문 | 기법 후보 | 데이터가 없으면 하지 말 것 |
|---|---|---|---|
| 매출·마케팅 | 어디서 전환이 깨지는가 / 어떤 고객이 매출을 만드는가 | 퍼널, 세그먼트, 코호트, 기여 분해 | 단계 없는 퍼널, 식별키 없는 고객 추적 |
| 학습 | 어떤 변수가 성과에 영향을 주는가 / 개인 기록 추적이 의미 있는가 | 드라이버, 궤적, 이탈 | 단면 데이터에서의 개인 궤적, 점수 예측만으로 결론 |

## 검증에서 확인한 것 (요약)

캐글에서 데이터셋을 고르고, 동일 공개본을 UCI·GitHub에서 받아 네 건을 실행했습니다. 원본 파일은 저장소에 넣지 않습니다.

| 케이스 | 채택 | 탈락 | 결과 요약 |
|---|---|---|---|
| 거래 매출 | 세그먼트·기여 | 퍼널(단계 없음) | 상위 20%가 학습 기간 순매출 72%, 이후 기간 55% |
| 시험 점수 | 드라이버 | 궤적(단면) | 준비 과정 +7.6점. 부모 학력은 처방하지 않음 |
| 주문 이행 | 시각 퍼널 | 상태값 나열 | 도착 97%. 상태 컬럼만으로는 퍼널이 아님 |
| 학습 이탈 | 조기 궤적 | 제출 횟수 개입(누수) | 과제 없음 이탈 79% vs 있음 21% |

테스트 후 Rule·Skill에 반영한 것: 상태 컬럼 ≠ 단계 로그, ID 이름 ≠ 사람 단위, 결과 재정의 변수를 개입 레버로 쓰지 않기, 해석 전 임원진/대중 gate.

## ver0에서 일부러 하지 않은 것

- 모든 도메인의 기법 백과사전
- 공통 분석 런타임이나 캐글 다운로드 스크립트
- 자동 모델 선정, AutoML, 대시보드
- `.cursor/` 공통 Rule·Skill로 승격
- 케이스별 testing 파일을 예시에 보관

## 추후 과제

- view→cart 이벤트 로그로 퍼널 과잉 적용 여부
- Skill 없는 대조 실행
- 입도 점검 Script 분리
- `.cursor/` 승격

## 예시 출력 골격

Skill의 설계 메모와 보고서 형식과 동일합니다. 해석·보고서는 독자 gate 이후에만 작성합니다.

```md
## 분석 설계 메모

- 질문:
- 도메인 / 분석 단위:
- 독자: 임원진 / 대중
- 채택 기법:
- 탈락 기법과 이유:
- 종속변수:
- 설명변수 (개입 / 맥락 / 제외):
- 비교 대상:
- 검증 방법:
- 이번엔 하지 않을 것:
- 가정:

## 한눈에 보기

- 결정 또는 질문:
- 핵심 결과: 독자 단위로 1~2문장
- 근거 강도: 강함 / 중간 / 약함
- 다음에 할 일: 1~2개
```

> 이 예시는 정답 분석 기법을 자동으로 고르는 시스템이 아니라, Agent가 분석 설계를 건너뛰지 않게 만드는 보조 도구입니다.
