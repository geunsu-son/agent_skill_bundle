# Session Market Briefing Automation

Skill이 **무엇을 어떻게 수행할지** 정의한다면 Automation은 **언제 실행할지** 정의합니다.

이 문서는 현재 운영 중인 예약 브리핑을 바탕으로 작성한 ver0 명세이며, GitHub 저장소 자체에서 예약 작업을 실행하지는 않습니다.

## 현재 예약

- 시간대: `Asia/Seoul`
- 실행 요일: 월요일~금요일
- 실행 시각: 07:30, 20:30

```ical
BEGIN:VEVENT
DTSTART:20260629T073000
RRULE:FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR;BYHOUR=7,20;BYMINUTE=30;BYSECOND=0
END:VEVENT
```

## 실행 시각별 목적

| KST | 목적 | 현재 예약 여부 |
|---:|---|---|
| 07:30 | 아시아 세션 준비 | 등록 |
| 15:30 | 런던 세션 준비 | 미등록 |
| 17:30 | 런던 초기 반응 확인 | 미등록 |
| 20:30 | 뉴욕 세션 준비 | 등록 |
| 21:30 | 뉴욕 본게임 직전 | 미등록 |
| 23:30 | 뉴욕 핵심 변동성 확인 | 미등록 |

Skill은 여러 시각의 목적을 지원하지만, Automation은 필요한 시각만 선택해 실행할 수 있습니다.

## Automation이 전달할 최소 요청

```text
현재 실행 시각에 해당하는 세션 목적을 식별하고,
session-market-briefing Skill에 따라 최신 경제·시장 브리핑을 작성한다.
```

상세 조사 절차와 출력 형식을 Automation 프롬프트에 반복해서 넣기보다 Skill에 유지하는 것이 목표입니다.

## 역할 분리

```text
Rule
시장 판단과 표현에서 지켜야 할 기준

Skill
세션 식별 → 조사 → 시장 반응 확인 → 방향 판정 → 출력

Automation
평일 07:30과 20:30에 Skill 실행 요청
```

## ver0에서 확인할 점

- 같은 Skill이 아시아와 뉴욕 세션 목적을 제대로 구분하는가?
- Automation 프롬프트를 짧게 줄여도 출력 품질이 유지되는가?
- 실행 시각이 추가될 때 Skill 수정 없이 예약만 추가할 수 있는가?
- 브리핑 후속 확인이 필요하면 별도의 Automation으로 분리하는 편이 좋은가?

## 변경 원칙

실제 예약 작업은 이 문서와 자동으로 동기화되지 않습니다. 예약 내용을 변경한 경우 문서도 별도로 갱신해야 합니다.
