# MCP Server Auth

## 상태

`ver0` draft. `purple-context-mcp` README로 확인한 참고 경로: 호출자는 Google Workspace 신원, 서버는 클라우드 워크로드 신원(IRSA 등), 데이터는 공유 검색 백엔드. GCP Drive 위임이 기본 경로가 아니다.

## 목적

공유 MCP 서버의 **호출자 신원**과 **워크로드 신원**을 나누고, 도구 표면에 맞는 최소 권한만 연다. 콘솔에서 사람이 할 일과 코드가 할 일을 구분한다.

자격 증명 값을 수집·출력·커밋하지 않는다.

## 사용 시점

- 팀 공유 MCP를 새로 만들거나 백엔드·허용 범위를 바꿀 때
- 개인 클라우드 키로 백엔드를 부르기 어려운 때 (MFA·IP 제한, 계정 없는 구성원)
- `mcp-server-scope` 이후, 구현 전

로컬 stdio에 개인 자격만 쓰는 서버면 이 Skill을 짧게만 적용한다. 시크릿 이름과 `.gitignore`만 적고 공유 인증을 설계하지 않는다.

## 입력

- 도구 목록과 백엔드 권한 힌트
- 왜 공유 서버인지 (개인 IAM 불가, 감사, 계정 없는 사용자)
- 실행 위치 (로컬 / 클러스터)
- 호출자를 회사 도메인만 볼지, 명단까지 볼지

## 판단: 두 겹

도구 표면이 정해진 뒤에 고른다. 넓은 권한을 먼저 받지 않는다.

| 겹 | 질문 | 참고 서버 |
|---|---|---|
| 호출자 | 누가 검색하는가 | 회사 Google ID 토큰. `hd`+`email`+`email_verified`+서명. 토큰은 로그에 안 남김 |
| 워크로드 | 서버가 백엔드를 어떻게 부르는가 | 파드 역할(IRSA 등). 사용자 액세스 키 없음 |

개인 그룹에 Deny(MFA·IP)가 있으면 그 그룹의 키를 서버에 넣지 않는다. Deny 대상이 아닌 워크로드 역할을 쓴다.

감사가 필요하면 **공유 정적 bearer를 두지 않는다**. 모든 호출이 개인 회사 계정이어야 “누가”가 비지 않는다.

회사 도메인만으로는 전사 검색이 열린다. 그 데이터가 민감하면 인증 통과 뒤 **명단**을 한 번 더 본다.

## 절차

### 1. 워크로드 권한을 도구에 매핑

도구마다 백엔드 액션을 적는다. 도구에 없는 권한을 역할에 넣지 않는다.

예: `retrieve` → 검색 API 읽기 한 종류. 계정·버킷 관리 권한은 제외.

JSON 키·장기 액세스 키를 컨테이너에 넣는 경로를 기본값으로 두지 않는다.

### 2. 호출자 인증

팀 공유 원격이면 다음을 정한다.

- 무엇을 검증하는가 (서명, issuer, 회사 도메인, 메일 인증 여부)
- `aud`만으로 막지 못하는 경우(사람이 받는 토큰의 audience가 전용 클라이언트가 아님) 회사 도메인 클레임이 실제 게이트인지
- OAuth 브라우저 로그인을 쓸지. Google은 동적 클라이언트 등록을 지원하지 않아 **표준 MCP OAuth 자동 플로우가 막힐 수 있다**. 우회를 만들면 콜백 URL 허용 목록이 통제점이다. 그 목록을 환경 변수로 열지 않는다 — 코드 리뷰를 건너뛰게 된다
- 인증 설정이 불완전하면 부팅 실패. 조용한 전면 401을 기본으로 두지 않는다

401과 403을 섞지 않는다. 명단 거부는 403이다.

### 3. 사람이 할 일 (콘솔·시크릿)

값을 붙여 넣으라고 하지 않는다. 체크리스트만 넘긴다.

1. 백엔드 API·역할을 도구 권한만으로 부여 (워크로드 신원)
2. 호출자용 Google OAuth 클라이언트 또는 ID 토큰 audience 목록
3. 시크릿은 시크릿 매니저 → 런타임 주입. git에 두지 않음
4. (해당 시) 명단·감사 DB. 기록 계정과 열람 계정을 나눔
5. 관리자 HTTP는 공용 인그레스에서 제외 + 별도 시크릿

사용자가 “역할 붙였다 / 시크릿 넣었다”고 한 것만 사실로 적는다.

### 4. 코드가 할 일

- 환경 변수 **이름**만 문서화. 기본값에 시크릿을 넣지 않음
- 호출자 이메일은 감사·레이트리밋·로그에 쓰고, 토큰 원문은 쓰지 않음
- 레이트리밋은 NAT 앞에서는 IP가 아니라 호출자 신원
- 명단 저장소 장애는 fail-closed(거부). 감사 적재 실패는 본래 검색을 막지 않을 수 있음. 반대로 감사를 켰는데 DB에 연결되지 않으면 부팅을 막음
- 401·403·429는 재시도하지 않음

### 5. 검증 (값 없이)

- 워크로드 역할 = 도구 권한
- 공유 정적 토큰 경로가 없음
- 시크릿 이름이 코드·차트와 같고 값은 없음

실제 호출 성공은 `mcp-server-connect`의 읽기 1건에서 확인한다.

## 출력 형식

```md
## 인증 요약

- 공유 서버가 필요한 이유:
- 호출자: (예: 회사 Google ID 토큰)
- 워크로드: (예: IRSA / 로컬 ADC)
- 명단: on / allow-all

## 도구–권한 표

| 도구 | 백엔드 액션 |
|---|---|

## 콘솔 체크리스트

완료/미완료. 값 없음.

## 코드 설정

환경 변수 이름. 부팅 실패 조건.

## 위험

정적 토큰, 광역 IAM, 공용 관리자 경로, 401/403 혼동.
```

## 완료 조건

- 호출자 신원과 워크로드 신원이 갈라져 있음
- 워크로드 권한이 도구와 같거나 더 좁음
- 공유 정적 토큰을 기본으로 두지 않음
- 시크릿 값이 출력·저장소에 없음
- 401과 403의 쓰임이 적혀 있음

## 실패 조건

- Drive 위임·GCP 키를 기본 경로로 단정하기
- 사용자 IAM 키를 파드에 넣어 Deny 정책을 우회하려 하기
- 명단 거부에 401을 쓰기
- JSON 키·토큰을 예시 코드에 인라인
