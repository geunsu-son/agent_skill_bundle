# MCP GCP Workspace Auth

## 상태

`ver0` draft. 사내 `purple-context-mcp`의 실제 자격 증명 경로는 이 환경에서 확인하지 못했습니다. GWS + GCP 권한으로 서버를 연다는 설명과 공개 GCP/Workspace 문서에 기반합니다.

## 목적

GWS 데이터를 여는 MCP에 대해, **도구 표면에 맞는 최소 권한과 자격 증명 경로**를 정하고, 사람이 콘솔에서 해야 할 일과 Agent가 코드에서 할 일을 나눕니다.

자격 증명 값을 수집·출력·커밋하지 않습니다.

## 사용 시점

- GWS/GCP MCP를 새로 만들거나 도구를 추가해 스코프가 늘 때
- 로컬 stdio에 서비스 계정을 붙이거나, Cloud Run 등에서 ADC로 열 때
- `mcp-server-scope` 이후, 구현 전

GWS가 아니면 이 Skill을 쓰지 않습니다.

## 입력

- `mcp-server-scope`의 도구 목록과 권한 힌트
- GCP 프로젝트 (있으면)
- 실행 위치 (개발자 머신 / GCP 서비스)
- 위임이 필요한지 (특정 사용자 데이터 vs 서비스 계정 자체)

## 판단: 인증 경로

도구 표면이 정해진 뒤에 고릅니다. 넓은 권한을 먼저 받지 않습니다.

| 경로 | 맞는 상황 | 주의 |
|---|---|---|
| 사용자 OAuth (동의 화면) | 개인이 자기 Drive/캘린더만 | 팀 공유 서버에는 토큰 보관 부담 |
| 서비스 계정 + 도메인 전체 위임 | 조직 컨텍스트를 서버가 대신 읽음 | 스코프·위임 주체를 최소로. 슈퍼관리자 작업 |
| GCP ADC / 워크로드 아이덴티티 | 서버가 Cloud Run 등 GCP에 있음 | JSON 키 파일을 컨테이너에 넣지 않음 |

사내에서 “GCP 권한 설정으로 자격 증명을 연다”면 보통 **프로젝트 API 사용 설정 + 서비스 계정(또는 런타임 SA) + (필요 시) Workspace 위임**입니다. 키 파일을 git에 두는 경로를 기본값으로 두지 않습니다.

도메인 전체 위임은 해당 스코프로 도메인 사용자를 가장할 수 있습니다. 읽기 컨텍스트가 목표면 `*.readonly`만 적고, 위임 주체는 서비스용 계정 또는 요청자가 지정한 사용자로 제한합니다.

## 절차

### 1. 스코프를 도구에 매핑

도구마다 필요한 Google API와 OAuth 스코프를 표로 적습니다. 도구에 없는 API를 활성화하지 않습니다.

예: `search_docs` → Drive API + `drive.readonly`. Admin SDK는 목록에 없으면 제외.

쓰기 도구가 없으면 `drive` (전체) 대신 `drive.readonly`를 씁니다.

### 2. 사람이 할 일 (콘솔)

Agent가 GCP/Admin 콘솔을 대신 클릭할 수 없으면, 아래를 체크리스트로 넘깁니다. 값을 붙여 넣으라고 하지 않습니다.

1. GCP 프로젝트에서 사용할 API만 사용 설정
2. 런타임용 서비스 계정 또는 Cloud Run 런타임 SA
3. IAM: 프로젝트 편집자 대신 필요한 역할만 (예: 시크릿 접근)
4. GWS 사용자 데이터가 필요하면 Admin console에서 해당 클라이언트 ID + **표에 있는 스코프만** 위임
5. 시크릿은 Secret Manager 또는 로컬 env. JSON 키를 만들면 `.gitignore`와 파일 권한, 순환 계획을 적음

완료 여부는 사용자가 “API 켰다 / 위임했다”고 한 것만 사실로 적습니다. 추측하지 않습니다.

### 3. 코드가 할 일

- 자격 증명은 환경 변수 **이름** 또는 ADC. 기본값에 키 경로를 하드코딩하지 않음
- 위임이 있으면 `subject`(가장할 사용자)를 설정으로 받고, 전 도메인 루프를 기본 동작으로 두지 않음
- 스코프 배열은 1단계 표와 동일. 여분의 `cloud-platform` 스코프를 넣지 않음
- 인증 오류(`invalid_grant`, `access_denied`, 403)는 재시도하지 않고 권한 문제로 반환

### 4. 검증 (값 없이)

구현·연결 전에 확인할 수 있는 것만 합니다.

- 스코프 목록 = 도구 권한 힌트
- 위임 클라이언트 ID를 문서에 적을 때 키 파일 내용을 붙이지 않음
- 로컬에서 ADC/`gcloud auth` 사용 시, 키 파일을 채팅에 붙여 넣지 말 것을 한 줄로 안내

실제 API 호출 성공은 `mcp-server-connect`의 읽기 1건에서 확인합니다.

## 출력 형식

```md
## 인증 요약

- 경로: 사용자 OAuth / SA+위임 / ADC
- 프로젝트: (있으면 ID, 없으면 미정)
- 실행 위치: 로컬 / GCP

## 도구–스코프 표

| 도구 | API | 스코프 |
|---|---|---|

## 콘솔 체크리스트

사람에게 넘긴 항목. 완료/미완료.

## 코드 설정

환경 변수 이름, 위임 subject 설정 이름. 값은 비움.

## 위험

위임 범위, 쓰기 스코프, 키 파일 사용 여부.
```

## 완료 조건

- 인증 경로가 실행 위치와 맞음
- 스코프가 도구 목록과 같거나 더 좁음
- 쓰기·Admin 스코프가 목적 없이 없음
- 시크릿 값이 출력·저장소에 없음
- 콘솔 작업과 코드 작업이 구분됨

## 실패 조건

- 도구 표면 없이 프로젝트 편집자·광역 스코프부터 요청
- 도메인 위임에 `mail`/`drive` 전체 쓰기를 기본으로 넣음
- JSON 키를 예시 코드에 인라인
