# MCP Tool Implement

## 상태

`ver0` draft. SDK 버전은 고정하지 않습니다. 구현 시 해당 언어의 공식 MCP SDK 문서를 확인합니다.

## 목적

범위에서 정한 도구·리소스·프롬프트를 MCP 서버 코드로 구현합니다. 핸들러는 백엔드 호출, 오류 구분, 응답 상한을 포함합니다.

## 사용 시점

- `mcp-server-scope`(및 GWS면 `mcp-gcp-workspace-auth`) 이후
- 기존 MCP에 도구를 추가할 때

## 입력

- 도구·리소스 스케치
- 인증 경로와 환경 변수 **이름**
- 언어/기존 저장소 (있으면)
- transport (stdio / Streamable HTTP)

## 절차

### 1. SDK 선택

저장소에 서버가 있으면 그 스택을 유지합니다. 없으면 요청 언어 또는 팀 스택에 맞춥니다.

| 언어 | 출발점 (확인 후 사용) |
|---|---|
| TypeScript | 공식 `@modelcontextprotocol/server` (v2 기준 `registerTool`, `serveStdio` / Streamable HTTP). v1 `@modelcontextprotocol/sdk`만 있는 저장소는 기존 API를 유지하거나 마이그레이션을 명시 |
| Python | 공식 MCP Python SDK 또는 팀이 쓰는 래퍼 |

SDK API는 버전에 따라 바뀝니다. 기억으로 시그니처를 단정하지 말고 문서·패키지를 확인합니다. 신규 원격 서버는 SSE transport를 기본으로 두지 않습니다.

stdio 서버는 **로그를 stderr**로 보냅니다. stdout에 `console.log`를 넣지 않습니다.

### 2. 도구 등록

각 도구에 다음을 넣습니다.

- Agent가 고를 수 있는 **description** (언제 쓰고 언제 쓰지 않는지)
- 입력 스키마 (필수·선택, 기본 상한)
- 가능하면 readOnly / destructive 힌트(SDK가 지원하면)

핸들러 규칙:

- 인증 클라이언트는 요청마다 키를 읽지 말고, 프로세스 또는 요청 스코프에서 재사용
- 목록은 `pageSize`/`limit` 기본값을 작게 (예: 10~25), 최대값을 둠
- 본문은 길이 상한. Drive 파일 전체를 무제한으로 붙이지 않음
- 빈 목록은 성공+빈 결과. 403/401은 권한 실패. 5xx·429만 짧은 재시도

GWS 호출은 인증 Skill의 스코프 밖으로 나가지 않습니다. `fields` 파라미터로 응답을 줄입니다.

### 3. 리소스·프롬프트

범위에 있을 때만 구현합니다. 없으면 빈 핸들러를 만들지 않습니다.

리소스 URI는 안정적인 식별자(예: `gws://file/{id}`)로 두고, 목록과 읽기를 분리합니다.

### 4. 오류를 Agent가 읽게

도구 결과는 보통 `content` 텍스트입니다. 내부 스택 트레이스·토큰·키 경로를 넣지 않습니다.

| 상황 | 반환 요지 |
|---|---|
| 인자 부족 | 필요한 필드 |
| 인증·스코프 | 권한 문제, 콘솔에서 볼 항목 (값 없이) |
| 대상 없음 | not found |
| 상한 초과 | 잘렸음, 다음 페이지 방법 |
| 백엔드 일시 오류 | 재시도 가능 여부 |

### 5. 로컬에서 서버가 뜨는지

연결 설정 전에 프로세스가 기동하는지만 확인합니다.

- stdio: Inspector 또는 `tools/list`에 해당하는 SDK 예제
- HTTP: 프로세스 리슨, MCP 엔드포인트 경로

클라이언트 `mcp.json`과 스모크 호출은 `mcp-server-connect`로 넘깁니다.

## 출력 형식

```md
## 구현 요약

- SDK·버전 확인:
- 전송:
- 도구 N / 리소스 N / 프롬프트 N

## 도구

| 이름 | 입력 | 상한 | 오류 구분 |

## 코드 위치

파일·엔트리포인트.

## 미완

테스트하지 않은 핸들러, 스킵한 프리미티브.
```

코드가 결과물이면 README에 목적, 환경 변수 **이름**, 하지 않는 권한을 반영합니다. 예시 env에 실제 키를 넣지 않습니다.

## 완료 조건

- 범위의 도구가 모두 등록됨 (제외한 것은 범위 문서와 일치)
- 설명·입력 스키마·상한이 있음
- stdout 오염 없음 (stdio인 경우)
- 시크릿이 소스에 없음
- 인증 실패와 빈 결과를 구분함
