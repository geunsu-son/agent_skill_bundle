# Blog Style Writing

## 상태

`ver0` draft. 수집 → 스타일 팩 → 초고·첨삭을 한 흐름으로 묶는다. 상세 절차는 아래 Skill에 맡긴다.

## 목적

이미 블로그를 쓰는 사람이, 자기 글 문체를 재사용하는 Agent에게 **게시용 원고**까지 맡길 수 있게 한다.

## 사용 시점

- “내 블로그 스타일 학습해서 초고·첨삭까지 해줘”
- 수집만 / 팩만 / 원고만 아닌 **전체 파이프라인**

부분 요청이면 해당 Skill만 실행하고 이 문서는 순서를 확인하는 용으로만 쓴다.

## 관련 Rule·Skill

- Rule: [`rules/blog-style-writing.mdc`](../../rules/blog-style-writing.mdc)
- [`collect-blog-corpus`](../collect-blog-corpus/SKILL.md)
- [`build-style-context`](../build-style-context/SKILL.md)
- [`write-blog-manuscript`](../write-blog-manuscript/SKILL.md)
- 크롤: Web Crawler Craft (`web-crawler-craft`)

## 입력

- 본인 블로그 URL (수집이 필요할 때)
- 이번 글 주제와 넣어야 할 사실 (원고가 필요할 때)
- 있으면: 기존 스타일 팩 경로, 기존 초고, 최대 수집 편수

이미 있는 팩·코퍼스를 다시 만들지 않는다.

## 절차

### 1. 지금 어디부터인가

| 상태 | 시작 |
|---|---|
| 코퍼스·팩 없음 | 2 → 3 → 4 |
| 코퍼스만 있음 | 3 → 4 |
| 팩이 있고 주제만 있음 | 4 |
| 초고만 있고 첨삭 요청 | `write-blog-manuscript` 첨삭만 |
| fixture로 절차만 확인 | 수집 생략, fixture를 코퍼스로 3 → (선택) 4 |

이 저장소 안 검증은 fixture가 기본이다. 실제 URL이 없으면 수집을 가상으로 성공 처리하지 않는다.

### 2. 수집

`collect-blog-corpus`를 따른다. 크롤 실패면 팩·원고로 넘어가지 않는다.

### 3. 스타일 팩

`build-style-context`를 따른다. 일반론 팩이면 글쓰기로 가지 않고 팩을 고친다.

### 4. 원고

`write-blog-manuscript`를 따른다. 초고 후 첨삭까지가 기본이다. 초고만 요청되면 첨삭을 생략한다.

### 5. 보고

시크릿·원문 전문을 넣지 않는다.

## 출력 형식

```md
## 한눈에 보기

- 수행한 단계: 수집 / 팩 / 초고 / 첨삭
- 스타일 팩: 경로 또는 미생성 이유
- 원고: 있음 / 초고만 / 없음
- 게시: 사람 확인 남김 (미게시)

## 수집

편수, 경로, 한계. 생략이면 이유.

## 스타일 팩

말투·도입·맺음·하지 않는 것 한 줄씩. 변경 요약.

## 원고

최종 원고 위치 또는 본문.

## 사람 확인

## 한계와 가정
```

## 완료 조건

- Rule 금지 패턴을 어기지 않음
- 필요한 단계의 하위 Skill 완료 조건을 충족함
- 팩 없이 말투 원고를 완료로 보고하지 않음
- 자동 게시 없음

## 향후 Script 후보
