# Build Style Context

## 상태

`ver0` draft. 절차 확인용 fixture는 [`fixtures/sample-corpus/`](../../fixtures/sample-corpus/)다. 실제 저자 코퍼스로는 아직 검증하지 않았다.

## 목적

수집된 글에서 **관찰 가능한 문체**만 골라, 글쓰기 Agent가 로드할 스타일 프롬프트와 근거 콘텍스트를 만들거나 갱신한다.

## 사용 시점

- 코퍼스를 모은 뒤 처음 스타일 팩을 만들 때
- 새 글이 쌓여 팩을 고칠 때
- “내 블로그 말투 프롬프트 만들어줘”

## 관련 Rule·Skill

- Rule: [`rules/blog-style-writing.mdc`](../../rules/blog-style-writing.mdc)
- 코퍼스가 없으면 [`collect-blog-corpus`](../collect-blog-corpus/SKILL.md)를 먼저 수행한다
- 템플릿: [`templates/style-pack/`](../../templates/style-pack/)

## 입력

- 코퍼스 위치 (글 파일 또는 인덱스)
- 있으면: 기존 `profile.md` / `evidence.md`
- 있으면: 강조할 시리즈·기간 (예: 최근 기술 글만)

코퍼스가 이 예시의 fixture뿐이면 그 사실을 출력에 `가정`으로 적는다. 실제 저자 문체로 단정하지 않는다.

## 저장 위치 (가정)

소비 프로젝트 기본값:

```text
blog-style/
├── corpus/           # collect-blog-corpus 산출
└── style-pack/
    ├── profile.md    # 글쓰기 때 로드하는 프롬프트
    ├── evidence.md   # 주장별 짧은 인용
    └── corpus-index.md
```

## 절차

### 1. 코퍼스 충분성

- 글 편수, 평균 길이, 기간
- 한 플랫폼·한 시리즈에만 치우쳤는지

**5편 미만**이면 단정 문장을 줄이고 가정을 늘린다. 0편이면 중단하고 수집으로 돌린다.

### 2. 관찰 축

아래를 **코퍼스에서 찾은 것만** 채운다. 해당 없는 축은 “관찰 못 함”으로 남긴다. 일반 작법으로 메우지 않는다.

| 축 | 볼 것 |
|---|---|
| 말투 | 해요체 / 합니다체 / 반말, 1인칭 |
| 호흡 | 문장·문단 길이, 한 문단 문장 수 |
| 도입 | 첫 문장·첫 문단이 장면 / 결론 / 질문 / 맥락 설명 중 무엇인지 |
| 맺음 | 요약 공식, 다음 할 일, 여운. 상투적 맺음 사용 여부 |
| 제목 | 길이, 질문형, 기술 용어, 숫자 |
| 구조 | 소제목 빈도, 목록 vs 산문, 코드 블록 |
| 어휘 | 영어 식별자, 비유, 이모지, 독자 호칭 |
| 하지 않는 것 | 여러 글에서 반복해 안 나오는 패턴 |

### 3. 주장마다 근거

각 관찰은 `evidence.md`에 다음을 단다.

- 주장 한 줄
- 구분: `사실` (여러 글에서 동일) / `관찰` (경향) / `가정` (표본 부족)
- 짧은 인용 1~2개와 글 제목 또는 id
- 인용은 **한두 문장**. 글 전문을 팩에 복사하지 않는다

근거를 못 붙이면 그 주장은 `profile.md`에 넣지 않는다.

### 4. `profile.md` 작성

글쓰기 Agent가 **그대로 시스템/작업 프롬프트로** 쓸 수 있게 짧게 쓴다.

포함할 것:

- 이 저자가 쓰는 것 (말투, 호흡, 도입·맺음, 제목)
- 이 저자가 쓰지 않는 것
- 내용 제약: 제공되지 않은 경험·숫자를 만들지 말 것
- 표본 한계 한 줄

넣지 말 것:

- “독자에게 가치를 전달하라” 같은 일반론
- 다른 유명 블로거를 흉내 내라는 지시
- 코퍼스에 없는 이상적 구조 (서론-본론-결론 강제 등)

템플릿: [`templates/style-pack/profile.md`](../../templates/style-pack/profile.md)

### 5. 갱신

기존 팩이 있으면:

1. 새 관찰과 이전 `profile.md`를 대조한다
2. 바뀐 축만 수정한다
3. 출력에 **변경 요약**을 남긴다 (추가 / 완화 / 삭제)

전체 파일을 근거 없이 재생성해 덮지 않는다.

### 6. 출력

## 출력 형식

```md
## 한눈에 보기

- 코퍼스: N편, 기간, 평균 길이
- 팩 위치: ...
- 이번 작업: 신규 생성 / 갱신
- 표본 한계: ...

## 스타일 요약

말투, 호흡, 도입, 맺음, 하지 않는 것을 각각 한 줄.

## 변경 요약

신규면 “해당 없음”. 갱신이면 축별 차이.

## 사실 / 관찰 / 가정

세 가지를 나눈다.

## 다음

- 글 요청이 있으면 `write-blog-manuscript`
- 글이 더 필요하면 수집 범위
```

`profile.md`와 `evidence.md` 본문은 소비 프로젝트 파일로 저장하고, 채팅에는 요약만 반복해도 된다. 파일이 없으면 채팅에 전문을 쓴 뒤 저장 위치를 제안한다.

## 완료 조건

- 코퍼스 없이 팩을 만들지 않음
- `profile`의 각 지시가 `evidence`와 연결됨
- 일반 작법 문장으로 빈 축을 채우지 않음
- 갱신이면 변경 요약이 있음
- 글 전문이 팩에 재저장되지 않음

## 검증 (이 예시)

1. [`fixtures/sample-corpus/`](../../fixtures/sample-corpus/) 세 글을 코퍼스로 넣는다
2. 위 절차로 `profile`·`evidence`를 채운다
3. 통과: 해요체·짧은 문단·실패 장면으로 시작·교과서 맺음 없음이 근거와 함께 나온다
4. 실패: “명확하고 친절한 기술 블로그” 같은 일반론만 나오거나, fixture에 없는 합니다체를 지시한다

## 향후 Script 후보

- 문장 길이·종결어미 빈도 집계
- 기존 profile과 새 profile의 축 단위 diff

문체 해석 자체는 Script로 옮기지 않는다. 집계가 반복될 때만 분리한다.
