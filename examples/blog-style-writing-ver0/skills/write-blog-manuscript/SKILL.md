# Write Blog Manuscript

## 상태

`ver0` draft. 스타일 팩을 로드해 초고를 쓰고 첨삭한다. 게시 API는 다루지 않는다.

## 목적

기존 스타일 팩에 맞춰 초고를 쓰고, 같은 팩을 기준으로 첨삭해 **사람이 붙여 넣을 수 있는 원고**를 만든다.

## 사용 시점

- “이 주제로 내 말투로 초고 써줘”
- “이 초고를 내 블로그 문체로 첨삭해줘”
- 수집·팩 구축 다음 단계로 글까지 한 번에 요청된 때

## 관련 Rule·Skill

- Rule: [`rules/blog-style-writing.mdc`](../../rules/blog-style-writing.mdc)
- 팩이 없으면 [`build-style-context`](../build-style-context/SKILL.md) (필요 시 수집부터)
- 오케스트레이션: [`blog-style-writing`](../blog-style-writing/SKILL.md)

## 입력

- 주제, 하고 싶은 말, 넣어야 할 사실 (경험·숫자·링크는 요청자가 준 것만)
- 스타일 팩 경로. 없으면 소비 프로젝트 `blog-style/style-pack/profile.md`를 찾고, 없으면 팩 구축으로 보낸다
- 있으면: 독자, 목표 길이, 시리즈명, 기존 초고
- 초고만 / 첨삭만 / 둘 다. 없으면 **둘 다**

요청자가 주지 않은 개인 경험은 “있을 법한 일”로 채우지 않는다. 필요하면 빈칸·질문으로 남긴다.

## 절차

### 1. 팩 로드

`profile.md`를 읽고, 가능하면 `evidence.md`에서 도입·맺음·하지 않는 것만 확인한다.

팩이 없거나 fixture뿐인데 실제 저자 글처럼 단정해야 하면 중단하거나 가정을 명시한다.

### 2. 초고 (요청에 초고가 포함될 때)

1. 제목 후보 1~2개. `profile`의 제목 습관을 따른다
2. 본문은 `profile`의 말투·호흡·도입·맺음을 따른다
3. 소제목·목록·코드는 저자가 쓰는 빈도에 맞춘다. 저자가 소제목을 거의 안 쓰면 억지로 넣지 않는다
4. 내용 공백은 지어내지 않고 `[확인 필요: ...]` 또는 질문으로 표시한다

초고만 요청되면 3단계를 생략하고 아래 형식의 초고 섹션까지 출력한다.

### 3. 첨삭 (요청에 첨삭이 포함될 때)

초고(방금 쓴 것 또는 사용자가 준 것)를 다음 순서로만 고친다.

1. **문체**: `profile`과 어긋나는 말투·호흡·호칭·상투적 맺음
2. **구조**: 저자 습관에 맞는 도입·단락. 일반 “서론-본론-결론”으로 재배치하지 않음
3. **내용 안전**: Agent가 넣은 경험·수치·단정이 입력에 있는지. 없으면 삭제하거나 확인 필요로 되돌림
4. **게시 직전**: 제목, 첫 문단, 링크·코드 펜스, 빈 `[확인 필요]`

고친 이유를 첨삭 로그에 짧게 남긴다. “더 매끄럽게”만 적고 문체를 바꾸지 않는다.

첨삭만 요청됐는데 초고가 없으면 초고를 받지 않고 진행하지 않는다.

### 4. 사람 확인 항목

게시 가능이라고 해도 아래는 사람에게 남긴다.

- 사실·경험·숫자 확인
- 공개하면 안 되는 내부 정보
- 제목 최종 선택 (후보가 둘이면)
- 실제 플랫폼 붙여 넣기·태그·시리즈

플랫폼에 로그인하거나 글을 올리지 않는다.

## 출력 형식

```md
## 한눈에 보기

- 단계: 초고 / 첨삭 / 초고+첨삭
- 스타일 팩: 경로 또는 “없음 → 구축 필요”
- 게시: 사람이 할 일 (Agent 미게시)

## 원고

(첨삭까지 했으면 최종 원고. 초고만이면 초고.)

## 초고와의 차이

초고만이면 “해당 없음”. 아니면 문체·구조·내용에서 무엇을 왜 고쳤는지.

## 스타일 대조

지킨 축 / 못 지킨 축 / 팩에 없어 가정한 축.

## 사람 확인

- [ ] ...
```

## 완료 조건

- 스타일 팩 없이 “내 말투” 초고를 끝내지 않음
- 입력에 없는 경험·숫자를 본문 사실로 남기지 않음
- 첨삭이 문체를 일반 블로그체로 평탄화하지 않음
- 최종본과 사람 확인 항목이 구분됨
- 자동 게시 없음

## 검증 (이 예시)

fixture 코퍼스로 만든 `profile`을 쓰고, 주제만 준 뒤 초고+첨삭을 돌린다.

- 통과: 해요체·짧은 문단·장면형 도입이 유지되고, 없는 장애 일화가 안 생김
- 실패: 합니다체 보고서 문장, “마무리하며” 맺음, 허구 SLA 숫자

## 향후 Script 후보

없음. 문장 생성은 Agent 판단이다. 맞춤법 검사기가 반복되면 그때만 검토한다.
