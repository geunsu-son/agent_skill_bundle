# Portfolio Hosting Choice

## 상태

`ver0` 예시. 실제 배포 경험을 통해 비교 항목과 권장 로직을 수정할 예정입니다.

## 목적

이력서·포트폴리오 웹 배포 경로를 **Next.js + Vercel**과 **HTML + Cloudflare** 중에서 요청자 상황에 맞게 선택합니다. 장단점을 설명하고 근거와 함께 권장안을 제시합니다.

## 사용 시점

- 포트폴리오·이력 웹 사이트를 처음 만들기 전
- 기존 사이트를 다른 스택으로 옮기려 할 때
- `portfolio-site-build` 시작 전 스택이 정해지지 않았을 때

## 입력

- 기술 수준 (비개발자 / 기본 HTML·CSS / React·Next 경험 등)
- 유지보수 의지 (가끔 수정 / 자주 업데이트 / 거의 안 함)
- 확장 계획 (정적 소개만 / 블로그 / CMS / 다국어 / API 연동 등)
- 도메인·DNS 관리 가능 여부
- 비용·무료 티어 선호
- 빌드·CLI·Git 사용 편의
- (선택) 목표 커리어 — 개발 직무일 때 Next 경험 자체가 신호가 될 수 있음

## 비교 기준 (ver0)

다음 축으로 두 경로를 비교합니다.

| 축 | 설명 |
|---|---|
| 진입 장벽 | 학습·설정에 필요한 시간 |
| 유지보수 | 수정·배포 반복의 쉬움 |
| 확장성 | 페이지 추가, 컴포넌트, 데이터 연동 |
| 성능·호스팅 | CDN, 빌드, 캐시 |
| 비용 | 무료 티어, 대역폭·빌드 한도 |
| 도메인·DNS | 커스텀 도메인 연결 난이도 |
| 커리어 신호 | 지원 직무와 스택 선택의 정합성 |

## 경로별 장단점 (기본 서술)

### Next.js + Vercel

**장점**

- React 컴포넌트·레이아웃 재사용, 페이지 추가가 구조적으로 쉬움
- Git push 연동 배포, 프리뷰 URL, 롤백이 수월함
- 이미지 최적화·라우팅·메타 등 프레임워크 기능 활용
- 프론트엔드·풀스택 지원 직무에서 **구현 과정 자체**가 포트폴리오 신호가 될 수 있음
- 이후 블로그(MDX), API Route, 인증 등으로 확장 용이

**단점**

- Node.js·npm·빌드 파이프라인 이해가 필요
- 단순 정적 페이지만 필요할 때 과한 스택일 수 있음
- 의존성·빌드 실패 등 운영 포인트가 HTML 단일 파일보다 많음
- Vercel 무료 한도·벤더 종속 (다른 호스팅으로 이전 시 Next 설정 조정 필요)

**잘 맞는 상황**

- React/TypeScript·웹 개발 직무 지원
- 여러 페이지·프로젝트 상세·향후 기능 확장 예정
- Git·CI 친화적 워크플로를 원함
- 컴포넌트 기반 디자인 시스템을 코드로 유지하고 싶음

### HTML + Cloudflare (Pages / Workers 정적 호스팅)

**장점**

- HTML·CSS·(선택) vanilla JS만으로 즉시 이해·수정 가능
- 빌드 없이 파일 업로드 또는 Git 연동으로 배포 가능
- Cloudflare CDN·무료 티어·DDoS 보호 등 인프라 강점
- 단순 이력·포트폴리오에 **불필요한 프레임워크 부담**이 적음
- 정적 자산만으로도 빠르고 예측 가능한 결과

**단점**

- 페이지·섹션이 늘면 중복 HTML/CSS 관리 비용 증가
- 컴포넌트·템플릿 없이 확장 시 일관성 유지가 수동 작업에 의존
- 복잡한 인터랙션·데이터 연동은 별도 설계 필요
- (비개발 직무) HTML 직접 편집이 부담일 수 있음 — 이 경우 MD 기반 빌더 등 다른 경로 검토

**잘 맞는 상황**

- 한두 페이지 정적 소개·이력서 웹판
- 프레임워크를 쓰고 싶지 않거나 학습 시간이 제한적
- Cloudflare·DNS를 이미 사용 중
- 최소 의존성·최대 단순성을 원함
- 비개발 직무이지만 정적 사이트 한 번 배포 후 거의 수정 없음

## 절차

### 1. 요청자 상황 정리

입력 항목을 표로 짧게 정리합니다. 없는 항목은 가정으로 명시합니다.

### 2. 양쪽 경로 비교

위 장단점을 **요청자 상황에 맞게** 재서술합니다. 일반론만 나열하지 않습니다.

### 3. 권장안 제시

- **권장 경로** 하나와 **1~2문장 근거**
- **차선**과 언제 차선이 나은지
- 선택 시 **다음 단계** (어떤 Skill로 구현·배포하는지)

### 4. 사용자 확인

이미 사용자가 경로를 명시했으면 비교는 요약만 하고 해당 경로로 확정합니다.

## 출력 형식

```md
## 상황 요약

- 기술 수준 / 유지보수 / 확장 / 도메인 / 비용 선호
- 가정: ...

## Next.js + Vercel — 이 요청자에게

- 장점: (상황 맞춤)
- 단점: (상황 맞춤)

## HTML + Cloudflare — 이 요청자에게

- 장점: (상황 맞춤)
- 단점: (상황 맞춤)

## 권장

- 경로: Next.js + Vercel | HTML + Cloudflare
- 근거: ...
- 차선: ... (조건)

## 다음 단계

- 디자인: portfolio-design-research
- 구현·배포: portfolio-site-build (스택: ...)
```

## 완료 조건

- 두 경로의 장단점이 요청자 맥락에 맞게 서술됨
- 권장안과 근거가 명시됨
- 다음 Skill 연결이 명시됨
- 한 경로만 고집하지 않고 차선 조건이 있음

## 향후 Script 후보

- 스택 선택 체크리스트 자동 점수화
- Cloudflare / Vercel 배포 상태 확인
