# Implementation protocol

대규모 작업용 최소 구현·실행 가능 보고 프로토콜이다. Ponytail과
i-have-adhd에서 영감을 받았으며, 일반 작업용 `core/user-rule`의 원칙을
대체하지 않고 확장한다.

## 적용 순서

1. 작업의 목적·사용자·완료 결과를 한 문장씩 정의한다.
2. 전체 영향 범위와 기존 흐름을 확인하고, 변경할 함수의 모든 caller를 찾는다.
3. 기존 구현 → 표준 라이브러리 → 플랫폼 기능 → 설치된 의존성 순서로 재사용 가능성을 확인한다.
4. 결정·미결정·가정을 분리하고, 결과를 뒤집을 모호점은 사용자에게 질문한다.
5. 작업을 작은 단계로 나누고 각 단계에 산출물·검증·중단 조건을 지정한다.
6. 대표 샘플 또는 가장 작은 변경으로 방법을 검증한 뒤 전체 범위로 확장한다.
7. 보안·데이터 손실·접근성·회귀 검증을 확인하고 reviewer에 판정을 요청한다.

## 단계 보고

각 보고에는 다음만 포함한다.

- 현재 단계 / 전체 단계
- 이번 단계에서 완료된 산출물
- 검증 결과
- 다음 행동 하나

오류는 위치·원인·수정 방향으로 보고한다. 목록은 5개 이내로 유지하고,
완료되지 않은 작업을 완료로 표현하지 않는다.

## 최소화의 안전선

- 코드량 감소만으로 성공 판정하지 않는다.
- 의도적인 단순화에 알려진 한계가 있으면 `ponytail:` 주석에 한계와 upgrade path를 기록한다.
- 위험 등급이 높은 변경은 reviewer 통과만으로 종료하지 않고 사용자 확인을 받는다.
- 같은 사유의 reviewer 반려가 반복되면 기존 계획을 고집하지 말고 orchestrator의 escalation 규칙을 따른다.
