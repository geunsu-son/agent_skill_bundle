# Minimal implementation

[Ponytail](https://github.com/DietrichGebert/ponytail)에서 영감을 받은 선택형 검토 Skill이다. 목적은 **과잉 구현을 줄이고 필요한 최소 코드**를 고르는 것이며, 검증·보안·데이터 손실·접근성은 줄이지 않는다. `ponytail:` 마커는 “한계 목록”이 아니라, 더 단순한 선택의 **근거**(grep 가능)와, 의도적으로 미뤄 둔 단순화의 **upgrade path**를 남기는 보조 수단이다.

## 절차

1. 요청된 결과와 실제로 필요한 범위를 한 문장으로 정의한다. 존재할 필요가 없으면 만들지 않는다(YAGNI).
2. 변경 대상의 실제 흐름과 모든 caller를 확인한다. 읽기는 생략하지 않는다.
3. 아래 사다리에서 **처음 걸리는 단**을 고른다. 이미 이 저장소에 있으면 재사용하고, 표준 라이브러리·플랫폼 네이티브·설치된 의존성 순으로 확인한다. 한 줄로 되면 한 줄로 쓴다. 그 다음에만 “동작하는 최소”를 쓴다.
4. 선택한 후보가 보안·데이터 손실·접근성·검증을 줄이지 않았는지 확인한다.
5. non-trivial 변경이면 가장 작은 실행 가능한 검증을 남긴다.

## 출력

- 사다리에서 고른 단과, 추가하지 않은 것(새 의존성·추상화·범위 확장 등)을 각각 한 줄로 기록한다.
- 네이티브·stdlib·기존 코드 등으로 의도적으로 단순화했으면, 그 **이유**를 `ponytail:` 메모로 남긴다(예: `ponytail: browser has one`). 나중에 반드시 바꿔야 하는 단순화만 upgrade path를 함께 적는다.
- 구현보다 먼저 발견한 불확실성이 결과를 바꿀 수 있으면 질문한다.

이 Skill은 `core/user-rule`의 최소 변경 원칙을 대체하지 않는다. 상세한 절차가 필요한 작업에서만 호출한다.
